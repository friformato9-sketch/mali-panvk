## Fault and nearest allocation

At 11:58:33.308, kbase reported:

```text

sideband 0x000000711e004200
```

The CSF callback emitted the GPU mapping list immediately after the fault. It contains this VkDeviceMemory mapping:

```text

VA 0x711a000000 .. 0x711e000000 (size 0x4000000)
```

The nearest preceding bound VkBuffer is:

```text
VkBuffer 0xb40000732a72d090
memory offset 0x3c00000
VA 0x711dc00000 .. 0x711e000000 (size 0x400000, usage 0x25)
```

The reported VA is **0x4200 bytes beyond both the VkBuffer end and VkDeviceMemory mapping end**. No mapping in the emitted map list covers `0x711e004200`. This identifies the nearest logical buffer allocation, but does not yet prove the faulting shader descriptor referenced that buffer. The descriptor set logging added for v6 is intended to establish that link.

## Interpretation and next step

The fault is an unmapped GPU VA immediately beyond the last buffer in the 64 MiB allocation, consistent with an out-of-range access. Treat it as a candidate buffer overrun until the v6 descriptor log ties the descriptor/binding to this VkBuffer. Do not extend the allocation or alter bounds handling based on address proximity alone.

For repeat runs, clear logcat before launch and redirect with PowerShell. Decode redirected logs as UTF-16 (`Get-Content` or Python `encoding='utf-16'`); raw byte searches miss the PanVK records because of PowerShell's UTF-16 output encoding.
