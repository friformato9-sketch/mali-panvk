# G925 PanVK kbase CSF submit telemetry (2026-11-25)

## Purpose and scope

Three repeated AIO Vulkan cube runs were captured with opt-in PANVK_DEBUG=perf enabled. The flag was configured only on the AIO Graphics Test 64bit shortcut assigned to Winlator container PanVK_G925_Test (Proton 11.0-7 arm64ec). The System control shortcut and Container-1 were not changed.

The environment setting was reopened and verified to persist as PANVK_DEBUG=perf before launch. The factory/system Android Vulkan driver was not modified; no root access or privileged sysfs changes were used.

## Device and workload

- Device: Samsung Galaxy Tab S11 SM-X730, Immortalis-G925 / MT6991.
- OS / compatibility: Android 17; Winlator Ludashi 5.0; Proton 11.0-7 arm64ec.
- Custom ICD loaded: Mesa 27.0.0-devel-cdb8aa7/libvulkan_panfrost.so.
- Workload: AIO Graphics Test 64bit, Vulkan cube benchmark, 1280x720 guest desktop, 15 seconds.
- Launch arguments: --cube vk --bench 15 --autoclose 5.
- Each log contains two extra startup records from Winlator Explorer; statistics below use only the AIO benchmark process.

Across these three runs, average FPS was 1,786.54 (sample SD 99.61, CV 5.58%). Mean 1% low was 434.68 FPS (sample SD 8.80, CV 2.03%). The third run had lower average throughput; its cause was not established. A thermal status reading taken after a run was 0, but that is not evidence about device thermal state throughout the run.

These were three diagnostic-enabled runs, not an interleaved diagnostics-on/off experiment. Do not use this set to claim that the instrumentation has zero performance overhead or to compare directly with the earlier no-debug A/B campaign.

## Limitations

The telemetry records are host-side kbase submission instrumentation. They are not GPU execution timestamps, hardware queue-active cycles, or proof that vertex/tiler, fragment and compute execute concurrently on the GPU.

The AIO cube is a synthetic Vulkan workload, not BannerHub or a real game. Vulkan CTS, BannerHub and application-level validation remain outstanding. The absence of fault signatures is limited to the captured log windows.
