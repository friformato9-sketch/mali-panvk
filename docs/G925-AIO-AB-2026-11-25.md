# G925 AIO Vulkan A/B - 2026-11-25

## Test setup

- Device: Samsung Galaxy Tab S11 Wi-Fi, SM-X730, MediaTek MT6991, Immortalis-G925.
- Android 17 / SDK 36; Winlator Ludashi 5.0; Proton 11.0-7 arm64ec.
- AIO Graphics Test 64-bit, Vulkan cube workload.
- Identical arguments: --cube vk --bench 15 --autoclose 5.
- Guest desktop: 1280x720.
- Three runs per driver; every run measured 15.000-15.001 seconds.

## Driver identity

System control:
- AIO shortcut environment: Container-1.
- Winlator Renderer Driver: System.
- Winlator Vulkan Driver: System.
- Logcat identified GraphicsDriverExtraction: Adrenotools DriverID: System.

PanVK test:
- AIO shortcut environment: PanVK_G925_Test.
- Winlator Renderer Driver: PanVK Mesa 27.0.0-devel-cdb8aa7.
- Winlator Vulkan Driver: the same cdb8aa7 package.
- Logcat confirmed hook_android_dlopen_ext loaded libvulkan_panfrost.so from the Mesa 27.0.0-devel-cdb8aa7 package during all three valid runs.

The first apparent PanVK result was excluded: the XServer renderer used cdb8aa7, but the shortcut's separate Vulkan Driver still selected a4b8b6b. It was a mixed-driver run, not a valid measurement of the new guest Vulkan driver. Its CSV is archived on the Windows host under AIO-Hybrid-renderer-cdb8aa7-vulkan-a4b8b6b.

## CSF fault observations

For all three valid cdb8aa7 runs:
- The guest Vulkan loader opened the cdb8aa7 libvulkan_panfrost.so.
- Filtered logcat did not find GROUP_ERROR_FATAL, exception/status 0x24c00488, SHAREABILITY_FAULT, VK_ERROR, or an AIO assertion.
- AIO produced both the CSV and the 13-byte Vulkan summary report.

The prior 0x24c00488 / 0x88 CSF fault has therefore not reappeared in these three AIO runs after the CSG-scoped SYNC_WAIT candidate fix. This is encouraging physical-device validation, not proof that every workload or synchronization path is fixed.

## Interpretation and limitations

This is a large and repeatable AIO Vulkan cube benchmark difference in favor of the current PanVK build. It is not a BannerHub/game benchmark and must not be presented as an 82% real-game FPS uplift. The synthetic cube workload, Winlator compatibility layer, container-prefix differences and workload-specific behavior limit generalization.

PANVK_DEBUG=perf was not enabled for these runs. Therefore no per-submit CPU preparation, kbase ioctl duration, CPU semaphore fallback or queue-stream byte/count telemetry was captured. This A/B demonstrates valid benchmark output and absence of the previous CSF fault, but does not yet locate the driver-side time spent in queue submission or prove queue overlap is optimal.

Thermal status was 0 when checked after the run sequence. The device reported 89% battery; these readings are a post-test snapshot, not synchronized per-run thermal traces.

## Next steps: roadmap point 1

1. Enable PANVK_DEBUG=perf in the PanVK test shortcut process environment and verify PANVK_PERF records appear. Do not use TU_DEBUG variables.
2. Capture repeated PanVK logs and classify each submit by prepare, submit, cpu_wait, cpu_wait_fallback, queue calls and bytes.
3. Run an identical BannerHub scene on the System control and PanVK test shortcut, recording frame pacing and repeatability.
4. If CPU submit and waits are not dominant, use Mali-native queue activity, MCU and memory counters to assess vertex/tiler, fragment and compute overlap. Do not infer GPU queue activity from SurfaceFlinger FPS.

Keep Container-1 on System and retain the previous PanVK package for rollback.
